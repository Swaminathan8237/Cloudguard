# CloudGuard-Water — Simulation Dashboard

A dependency-free browser dashboard for the CloudGuard-Water presentation. It generates randomized synthetic telemetry, visualizes the latest 30 samples, provides adjustable input controls, and calls the existing FastAPI endpoints for actual model predictions and decision-path explanations.

## What is included

- Live synthetic pH, TDS, turbidity, and temperature samples (default interval: 4.5 seconds)
- Start/pause simulation and generate-one-sample controls
- Editable sliders and two fixed demonstration profiles
- Telemetry chart with a rolling history
- FastAPI readiness check using `GET /health`
- Real prediction requests using `POST /predict`
- On-demand decision-path request using `POST /explain`
- In-session prediction history
- Explicit `SIMULATION MODE — NO LIVE SENSOR DATA` notice
- No npm install, third-party CDN, or additional UI dependencies

## Run on Windows

1. Copy the `CloudGuard-Water-Simulation-Dashboard` folder into your CloudGuard project folder, or keep it separate.
2. Start your existing FastAPI backend from the **project root**, in a terminal:

   ```powershell
   python -m uvicorn api.main:app --reload --host 127.0.0.1 --port 8000
   ```

   Use your project's current virtual environment. The model artifact path must resolve as it does in your existing setup.

3. In a second terminal, move into this dashboard folder and run:

   ```powershell
   python -m http.server 5173 --bind 127.0.0.1
   ```

4. Open `http://127.0.0.1:5173` in Chrome or Edge.
5. Click **Check API**. The API should report that the service is healthy and the model is loaded.
6. Click **Start simulation**. Synthetic readings change approximately every 4.5 seconds. When the API is healthy, the dashboard sends those values to `/predict` and records responses.
7. Click **Explain result** to retrieve the latest `/explain` decision path.

The dashboard does not retrain, replace, or modify the dataset/model. It uses the existing four-feature request contract: `pH`, `TDS_ppm`, `Turbidity_NTU`, and `Temperature_C`.

## If the API connection fails

- Open `http://127.0.0.1:8000/health` directly. Verify that it reports `status: healthy` and `model_loaded: true`.
- Confirm that the configured base URL in the dashboard is `http://127.0.0.1:8000`.
- If the browser console reports a CORS error, add `http://127.0.0.1:5173` and `http://localhost:5173` to the **existing** FastAPI CORS allowlist, if your API's current configuration does not already permit them. Do not change the `/predict` or `/explain` schemas.
- If you use another port or host, update the dashboard base URL and the CORS allowlist consistently.

## Presentation notes

- All telemetry generated by this page is synthetic; it is not read from ESP8266/ESP32 or physical probes.
- Predictions and explanations are presented as actual model responses only when the API returns them. If the API is offline, the dashboard displays the error instead of fabricating a Safe/Unsafe prediction.
- A model output of `Safe` is a statistical classification, not a drinking-water certification. Physical inputs and this classifier cannot establish the absence of pathogens, heavy metals, or other unmeasured contaminants; laboratory testing is needed to determine actual potability.
- The fixed “Low-load profile” and “Elevated readings profile” are demonstration examples, not claims about sensor data or legal water-quality thresholds.
