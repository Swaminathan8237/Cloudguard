### Key Observations:
1. **High TDS Sensitivity**: When `TDS_ppm` exceeds approximately 500–700 ppm, the Decision Tree branches directly toward leaf #48 ($P(\text{Unsafe}) = 1.0000$), reflecting the strong association between dissolved solids and contamination in the canonical dataset.
2. **Audit Case #55037**: Case #55037 from the held-out test partition possesses benign physical readings ($pH=7.05, TDS=192.3, \text{Turb}=3.95, \text{Temp}=24.26$) and is classified as `Safe` ($P=0.9948$, Leaf #14), even though its historical label was `Unsafe`. This serves as an invaluable viva discussion tool demonstrating why statistical ML models require certified laboratory confirmation.
3. **Out-of-Distribution Resiliency**: When extreme values ($pH=11.20, TDS=3150$) are supplied, the API completes inference cleanly (HTTP 200) without crashing, but explicitly attaches 4 training-range warnings that are highlighted in amber on the dashboard.

## 4. Defensive Operational Guardrails & Failure Modes

The dashboard implements comprehensive defensive handling for all operational failure states:

1. **Pydantic Validation Errors (HTTP 422)**:
   - If manual input violates physical constraints (e.g., $pH = 15.2$ or $TDS = -20$), the API returns standard HTTP 422 with detailed field paths.
   - The dashboard catches the error and displays a clear red alert (`Pydantic Validation Error: field pH: Input should be less than or equal to 14`) without crashing or losing application state.
2. **Service Unavailable (HTTP 503)**:
   - If the ML model artifact is missing or corrupted, `GET /health` returns HTTP 503 and the status badge updates to `API DEGRADED`.
   - Prediction requests return HTTP 503 with the diagnostic message: `Model artifact is not loaded or currently unavailable`. The dashboard displays this clearly.
3. **Network Disconnection / Timeout**:
   - Polling requests utilize `AbortSignal.timeout(5000)`. If the backend becomes unreachable, the connectivity badge turns red (`API DISCONNECTED`), and the narrative box indicates `API Connectivity Error: Connection refused`.
4. **No Silent Fallback to Demo Data**:
   - In `Live ESP32 Standby` mode, the dashboard completely halts demo data simulation and displays the explicit hardware pending banner. It never silently substitutes simulated readings for missing live telemetry.
5. **Disabled Actuation**:
   - The dashboard provides no actuation buttons, relays, or triggers. Physical valves and pumps are strictly excluded from automated control.

## 6. Physical Hardware Commissioning Status & Limitations

### 6.1 Status Summary
- **Circuit Schematic**: Finalized in Phase 7.1/7.3 using Option D ($15\,\text{k}\Omega : 10\,\text{k}\Omega$, $M = 2.50\times$, $5.0\,\text{V} \to 2.0\,\text{V}$ mapping, ensuring $450\,\text{mV}$ ADC headroom).
- **Firmware**: Compiled successfully with `arduino-cli` using ESP32-WROOM-32 core (Flash: 79.06%, RAM: 14.81%).
- **Hardware Integration**: **STRICTLY PENDING**. Physical bench testing with live electrochemical probes, calibration buffer solutions (pH 4.01, 7.00, 9.21), and conductivity standards remains scheduled for future in-person hardware labs.

### 6.2 Limitations of the 4-Parameter Model
Students, developers, and viva examiners must note:
1. **Biological Pathogens**: Microscopic bacteria (*Escherichia coli*, *Vibrio cholerae*), viruses (noroviruses, rotaviruses), and protozoan cysts (*Giardia*, *Cryptosporidium*) have negligible impact on pH, TDS, turbidity, or temperature at infectious concentrations. A `Safe` prediction provides zero assurance against biological pathogens.
2. **Toxic Heavy Metals**: Lethal concentrations of lead ($> 0.01\,\text{mg/L}$), arsenic ($> 0.01\,\text{mg/L}$), or mercury ($> 0.001\,\text{mg/L}$) contribute fractions of a part per million to TDS and are undetectable by standard analog TDS probes.
3. **Statutory Standards**: Standardized laboratory analysis under statutory standards (e.g., WHO Guidelines for Drinking-water Quality or BIS IS 10500) remains legally and medically mandatory to certify potable water.
